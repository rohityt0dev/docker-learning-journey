# .dockerignore

## 📌 What is .dockerignore?

The `.dockerignore` file excludes unnecessary files and directories from the Docker build context. This helps reduce build time and prevents sensitive or unwanted files from being included in the build context.

## 🔹 Example

Create a file named `.dockerignore` in the project root:

```text
node_modules/
.git/
.env
*.log
README.md
.DS_Store
```

## 🔹 Common Patterns

| Pattern | Purpose |
|---|---|
| `node_modules/` | Exclude Node.js dependencies |
| `.git/` | Exclude Git history |
| `.env` | Exclude environment configuration |
| `*.log` | Exclude log files |
| `README.md` | Exclude the README file |
| `*.tmp` | Exclude temporary files |


## 🔹 How It Works

When you run:

```bash
docker build -t my-app .
```

Docker uses the current directory (`.`) as the build context. Files matching `.dockerignore` patterns are excluded from that context.

## 🔹 Best Practices

- Exclude unnecessary files to improve build efficiency.
- Exclude `.git/`, local dependencies, and temporary files.
- Keep secrets such as `.env` out of the build context.
- Do not copy secrets into images.
- Ensure files required by your Dockerfile are not excluded.

## 🧪 Practice

1. Create a `.dockerignore` file.
2. Add `node_modules/`, `.git/`, and `.env`.
3. Build your Docker image.
4. Check your Dockerfile's `COPY` instructions to ensure required files are not excluded.

## 🎯 Key Takeaway

The `.dockerignore` file helps keep Docker build contexts smaller, builds more efficient, and sensitive files out of the build context.
